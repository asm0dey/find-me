# find-me Demo UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A swing-tree window (`find-me --demo`) that runs the real find-me pipeline and shows it, for half of a vertical Short:
learning the face, listing albums, a paced scan with movie-style overlays, and a gallery of found photos.

**Architecture:** A background "director" thread in `Demo` runs the phases using `Faces` and `FindMe`'s listing/download
code and publishes immutable `DemoState` records into a swing-tree `Var<DemoState>`. The scan pipeline runs at full speed
and pushes results onto a queue; a `Pacer` takes them off at the display pace (0.15 s per miss, 1.5 s per match). The view
binds to the `Var` and paints photos and overlays with Java2D in one painter class.

**Tech Stack:** Java 25, Maven, swing-tree 1.1.1 (Sprouts `Var`, MigLayout), Java2D, existing ONNX Runtime + OpenCV +
GraalPy stack, JUnit Jupiter 6.

**Spec:** `docs/superpowers/specs/2026-10-20-demo-ui-design.md`. Final mockup (open in a browser):
`.superpowers/brainstorm/2739968-1792486923/content/all-screens-phone.html`. Read both before any task.

## Global Constraints

- The CLI (`findme.FindMe`) output, files (`seen.txt`, `matches.txt`) and behavior are unchanged. The demo writes neither file.
- One executable: the demo starts when the first argument is `--demo` (`find-me --demo <ref-dir> <album-or-dir>...`);
  without it, the CLI behaves exactly as before. `FindMe.main` hands off to `Demo.run(String[] rest)`; there is no
  second main class or second native image.
- Native image: `mvn -Pnative package` still builds the one `target/find-me`, and both modes work from it. Metadata stays
  per platform in `src/main/native-image/<platform>/`; record extra entries only for what actually fails (Liberica NIK
  supports AWT/Swing out of the box).
- Content area exactly 1080×960 device pixels, not resizable. Force scale 1: `System.setProperty("sun.java2d.uiScale", "1")`
  first thing in `main`, and `SwingTree.initializeUsing(cfg -> cfg.uiScaleFactor(1f))` before building the UI.
- Phone readability minimums at 1080×960: no text under 32 px; labels 32–36 px; header numbers ≥ 64 px; "MATCH" ≥ 120 px;
  end-screen count ≥ 200 px; face box stroke ≥ 6 px; landmark dots ≥ 12 px across; ✓/✗ ≥ 160 px. Drop, don't shrink.
- Colors: background `#0F172A`, card `#1B2336`, muted `#94A3B8`, match `#22C55E`, no match `#EF4444`, scanning `#38BDF8`,
  landmarks `#FDE047`, text `#F8FAFC`, bar track `#272F42`.
- Font: Pragmasevka Nerd Font Regular + Bold, bundled from `/usr/share/fonts/TTF/pragmasevka-nf-{regular,bold}.ttf`.
- Scores show as percent: `round(similarity × 100)` + `"%"`, clamped to 0..100 for display. Threshold shows as `40%`.
- Copy, verbatim: `LEARNING`, `LISTING`, `FOUND n`, `YOU`, `YOU · n`, `photos found`, `Python inside the JVM`,
  `album k/n`, `slowed down`, `similarity n%`, `threshold 40%`, `MATCH`, `of N`, `real s.s s`, `+N more`,
  `NOT FOUND`, `your face → 512 numbers → averaged`.
- Pacing: miss 150 ms, match hold 1500 ms, lock-on 300 ms. Tunable constants in one place.
- swing-tree: follow its agent guide, `docs/agent-skills/SKILL.md` in codeberg.org/globaltcad/swing-tree (§7 styling,
  §9 animation, §11 threading, §13 HiDPI, §14 gotchas). The EDT only ever reads immutable values.
- Pin every dependency version; swing-tree's own deps are ranges, so pin them in `dependencyManagement`.

## Review Focus

- **EXIF-rotated photos:** boxes must sit on the faces. Draw the photo from the same OpenCV-decoded `Mat` the detector saw
  (`Faces.decode` applies EXIF), never via `ImageIO`. Test in Task 2.
- **Huge local photos (6000 px):** display images are downscaled to ≤ 1080 px long side with boxes scaled to match; the queue
  holds bytes, not decoded images. Test in Task 2.
- **Failed downloads/decodes:** not shown, but the `n / N` counter still advances so it ends at `N / N`. Test in Task 5.
- **No usable reference photos, or gallery-dl raising on an album:** the window shows the message instead of hanging or
  exiting silently. Test in Task 5.
- **Negative similarity (cosine can be < 0):** shows `0%`, bar empty, never `-5%`. Test in Task 1.

### Task 2: Per-face detections and display images from `Faces`

**Files:**
- Modify: `src/main/java/findme/Faces.java`
- Test: `src/test/java/findme/FacesTest.java`

**Interfaces:**
- Produces:
  - `record Face(float x1, float y1, float x2, float y2, float[] landmarks, float[] embedding)` (nested in `Faces`,
    package-private; `landmarks` is 10 floats x,y in source-image pixels; `embedding` L2-normalized 512-d).
  - `List<Face> faces(Mat img)` — detection + embedding per face. `embeddings(Mat)` becomes
    `faces(img).stream().map(Face::embedding).toList()` so the CLI's numbers are unchanged.

    is ≤ `maxSide` (no upscaling).
  - `record Shown(BufferedImage image, float scale)` is **not** needed: callers compute
    `scale = image.getWidth() / (float) mat.cols()` and multiply face coordinates by it.

### Task 5: Director and Pacer

**Files:**
- Create: `src/main/java/findme/Pacer.java`, `src/main/java/findme/Demo.java`
- Modify: `src/main/java/findme/FindMe.java` (`--demo` hand-off in `main`, usage line)
- Test: `src/test/java/findme/PacerTest.java`

**Interfaces:**
- Consumes: Task 2 `Faces.faces/alignedCrop/toImage/decode`; Task 3 `FindMe.*`; Task 4 `DemoState.*`; Task 1 `Theme` pacing.
- Produces:
  - `sealed interface Result { record Scored(byte[] bytes, List<Faces.Face> faces, float best) ; record Failed() }`
    (nested in `Pacer`).
  - `final class Pacer` with `Pacer(BlockingQueue<Result> queue, int total, Consumer<DemoState> publish, Sleeper sleeper)`;
    `interface Sleeper { void sleep(long ms) throws InterruptedException; }` so tests run without real waiting;
    `void pipelineFinished()`; `List<Shot> run()` (blocks until `total` results consumed, returns matches sorted
    by similarity, descending). `static long holdMs(Result r)` → `MATCH_MS` if `best ≥ THRESHOLD`, `MISS_MS` for a miss,
    `0` for `Failed`. `slowedDown` in each published `Scanning` = `!queue.isEmpty() || pipelineFinished`.
  - `final class Demo` with `static void run(String[] args)` (args after `--demo`: same as the CLI's). `FindMe.main`
    calls it when `args[0]` is `--demo`, after setting the Truffle property it already sets. Usage line for both modes:
    `usage: find-me [--demo] <reference-photos-dir> <album-url-or-dir> [<album-url-or-dir> ...]`.

Director sequence (in `Demo`, on one background thread; the view only receives `DemoState` values):
1. `ensureModels()`; open `Faces`.
2. Learning: for each reference file (sorted, as the CLI), decode, `faces`; skip unless exactly one face; publish
   `Learning` with the new 448 crop (converted with `toImage(crop, 448)`) and the photo as `current` with its one box
   (no verdict). Average with `FindMe.average`. Zero usable → publish `Failed("no usable reference photos")` and stop.
3. Listing: `listDir` for directories, `listAlbums` for links, publishing `Listing` from the progress callback, plus a
   ticker that republishes `elapsedMs` every 100 ms. Pass an empty `seen` set (the demo always rescans everything).
   An exception → `Failed(<exception message>)`.
4. Scan: start `realScan = System.nanoTime()`; same pattern as `FindMe.scan` (virtual threads, `IN_FLIGHT` semaphore,
   `CPUS` semaphore), each task downloads/reads, runs `faces`, and `queue.put`s `Scored` or `Failed`. Stop the clock when
   the executor closes, then `pacer.pipelineFinished()`. The pacer runs on its own thread; its `Shot`s are built from
   `toImage(decode(bytes), 1080)` with boxes scaled by `image.getWidth() / mat.cols()`.
5. Done: publish `Done(crops, total, matches, realScanMs)`.

### Task 6: The window

**Files:**
- Create: `src/main/java/findme/DemoView.java`, `src/main/java/findme/PhotoPainter.java`
- Modify: `src/main/java/findme/Demo.java` (show the view instead of printing)

**Interfaces:**
- Consumes: `Var<DemoState>` (Sprouts) updated by the director via `UI.run`; `Theme`; `DemoState.grid`.
- Produces: `static JComponent DemoView.create(Var<DemoState> state)`; `PhotoPainter` static methods
  `paintShot(Graphics2D g, Rectangle area, Shot shot, float lockOn, boolean verdict)`,
  `paintStamp(Graphics2D g, Rectangle area, float similarity, float progress)`, `paintTile(Graphics2D g, Rectangle area, Shot shot)`.
  `lockOn` and `progress` are 0..1 animation fractions computed from `Scanning.shownAtNanos` and `Theme.LOCK_ON_MS`.

Layout per phase, matching `all-screens-phone.html` at 1080×960 (40 px padding, 28 px gaps, left column 300 px):
- Header: left title (`LEARNING` / `LISTING` / `FOUND n`, bold 72 px; green when `found > 0`), right block (muted bold 44 px:
  `done / total`, `album k/n` + `mm:ss`, or `shown / total` with `slowed down` in yellow 34 px beneath, only while
  `slowedDown`).
- Left column: `YOU` / `YOU · n` (36 px muted) over a 3-column crop mosaic with 8 px gaps; as many full rows as fit;
  if crops overflow, the last tile reads `+K` (K = crops not shown + 1).
- Right area: Learning → `paintShot` in scanning blue, footer line `your face → 512 numbers → averaged` (36 px);
  Listing → card with `found` at bold 240 px, `photos found`, `Python inside the JVM` (yellow, 44 px);
  Scanning → `paintShot`, then the bar row (`similarity n%` / `threshold 40%`, 38 px; 34 px tall bar, white 6 px tick at 40%,
  fill green or red by verdict) and, for a match, `paintStamp` (`MATCH` 130 px bold, `similarity n%` 46 px, rotated −6°,
  8 px green border, on 75% background). Verdict ✓/✗ 180 px in the bottom-right corner for misses.
- Done: header `FOUND n` (green) and right block `of N` / `real s.s s`; body is the `grid(n)` of `paintTile`
  (photo + green box + score tag), last tile `+N more` when `grid.more() > 0`; zero matches → `NOT FOUND` in 120 px red,
  centered. Failed → the message in 44 px, centered, red.
- Box style: 6 px stroke, score tag above the box (bold 44 px on the box color); glow on matches as 3 extra strokes of
  8/14/20 px at 35/20/10% alpha; landmark dots 14 px. Skip a face's score tag when the face box is narrower than the tag
  (crowded photos) — the best face always keeps its tag.
